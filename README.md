# DocMind — Retrieval-Augmented Generation service

[![CI](https://github.com/R2Vve2/docmind-rag/actions/workflows/ci.yml/badge.svg)](https://github.com/R2Vve2/docmind-rag/actions/workflows/ci.yml)

A production-style **RAG (Retrieval-Augmented Generation)** system that answers questions about your own
documents with **cited, grounded answers**. Built from first principles in Python with no LangChain, so every
stage of the pipeline is visible and testable.

```
 .md / .txt / .pdf ──► chunking ──► ┌─ dense embeddings (bge-small, ONNX) ─┐
                                    │                                       ├─► Reciprocal Rank Fusion ─► top-k
                                    └─ BM25 sparse index ──────────────────┘          │
                                                                                       ▼
                               FastAPI + web UI ◄── answer with [n] citations ◄── Claude (or offline extractive backend)
```

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt

# 1. index the sample corpus (4 fictional company documents)
python -m docmind ingest data/sample_docs

# 2. ask a question from the terminal
python -m docmind ask "How many days of annual leave do full-time employees get?"

# 3. or run the API + web UI
uvicorn docmind.api.app:app --reload        # open http://localhost:8000  (docs at /docs)
```

Without an `ANTHROPIC_API_KEY` the service uses a deterministic **extractive** backend that still returns cited
sentences, so everything works offline. Add a key to `.env` (see `.env.example`) and answers are generated by
Claude (`claude-opus-5-5` by default) with server-side refusal fallback enabled.

### Docker

```bash
docker compose up --build          # http://localhost:8000
```

The compose file mounts a volume for the persisted index and the cached embedding model.

## Architecture

| Layer | Module | Notes |
|---|---|---|
| Ingestion | `docmind/ingest/` | Loaders for txt/md/pdf; recursive character chunker (paragraph → line → sentence → word) with overlap |
| Dense retrieval | `docmind/retrieval/embeddings.py`, `vector_store.py` | `FastEmbedEmbedder` (BAAI/bge-small-en-v1.5, 384-d, ONNX, CPU) or `HashingEmbedder` (offline); NumPy cosine index with save/load |
| Sparse retrieval | `docmind/retrieval/bm25.py` | BM25Okapi over a stop-word-filtered tokenizer; exact matches for part numbers, names, codes |
| Fusion | `docmind/retrieval/hybrid.py` | Reciprocal Rank Fusion, no score calibration needed |
| Generation | `docmind/generation/` | `ClaudeLLM` (Anthropic SDK) / `ExtractiveLLM`; strict grounding prompt; `[n]` citations mapped back to chunks |
| Service | `docmind/api/` | FastAPI app factory, pydantic schemas, lifespan loads/saves the index |
| Evaluation | `docmind/evaluation/` | Golden set runner producing a scorecard + JSON report |

### Design decisions

- **Hybrid retrieval.** Dense embeddings capture paraphrases ("how long is the guarantee" → *warranty*), BM25 captures
  exact tokens ("NXC-4", "ISO 10218-1"). RRF merges them without tuning score weights.
- **Over-fetch then fuse.** Each retriever returns 4× `top_k` candidates before fusion, so a chunk ranked well by only
  one retriever still has a chance.
- **Grounding by construction.** The prompt forbids outside knowledge and requires a fixed refusal sentence when the
  context is insufficient. Citations are parsed and validated against the retrieved chunks; invalid markers are dropped.
- **Offline-first testing.** The hashing embedder and extractive LLM make the full pipeline (including the API) testable
  in CI with zero network calls and zero cost. The same tests exercise the real code paths.
- **Swappable backends.** Embedder and LLM are protocols; swapping in another vector DB or model is a one-file change.

## Evaluation

`python -m docmind.evaluation.run_eval` indexes `data/sample_docs`, runs the 15 questions in `eval/golden.jsonl` and prints:

```
                hit_rate: 1.000      # expected document in top-5
                     mrr: 1.000      # mean reciprocal rank of the first correct chunk
          keyword_recall: 0.933      # expected facts present in the answer
      citation_precision: 0.900      # citations that point at the expected document
  answers_with_citations: 1.000
```

(Results above: `fastembed` embeddings + extractive backend, measured on this corpus.) CI runs the same evaluation and
fails the build if hit@5 drops below 0.9, which turns retrieval quality into a regression test.

## API

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/health` | Index size, active embedder and LLM backend |
| `POST` | `/ingest/text` | Index an inline document `{title, text}` |
| `POST` | `/ingest/files` | Multipart upload of `.txt/.md/.pdf` files |
| `GET` | `/documents` | List indexed documents |
| `DELETE` | `/documents/{id}` | Remove a document and its chunks |
| `POST` | `/query` | `{question, top_k}` → answer, citations, retrieved chunks with dense/sparse ranks |

## Configuration

All settings are environment variables prefixed `DOCMIND_` (see `.env.example`): embedder, embedding model,
chunk size/overlap, `top_k`, RRF constant, index directory, LLM backend and Claude model.

## Deployment (public demo mode)

Three settings make the service safe to expose publicly:

| Variable | Effect |
|---|---|
| `DOCMIND_READ_ONLY=true` | Ingest and delete endpoints return 403; the UI hides the upload panel |
| `DOCMIND_SEED_DIR=data/sample_docs` | Indexes the folder at start-up when the index is empty |
| `DOCMIND_RATE_LIMIT_PER_MINUTE=20` | Caps `/query` calls per client IP (returns 429 with `Retry-After`) |

The Docker image bakes in the embedding model, so containers start without downloading anything, and the running
demo uses about 250 MB of memory. Ready-made configs are included for three hosts:

- **Render (free plan):** in the Render dashboard choose New, Blueprint, pick this repository and apply. `render.yaml`
  sets the demo variables. Free instances sleep after 15 idle minutes and take about a minute to wake.
- **Fly.io:** `flyctl launch --no-deploy --copy-config` then `flyctl deploy`, using `fly.toml` (scales to zero when idle).
- **Hugging Face Spaces:** Docker Spaces require a PRO subscription. Create a Docker Space, push this repo with
  `deploy/huggingface/README.md` as the Space README, and set the three variables above in the Space settings.

Keep `DOCMIND_LLM=extractive` on a public deployment unless you add a Claude key deliberately: the rate limit
bounds abuse, but every Claude-backed question is billed to your key.
